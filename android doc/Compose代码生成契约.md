# Compose 代码生成契约（@compose → Kotlin Compose 函数）

> 本文档规定 **SfA 插件**如何把 Sublimation 的 `@compose` 代码**在编译期**展开成
> Kotlin（Jetpack Compose，Material 3）函数，以及桌面 JS 目标如何与生成的 Kotlin 保持语义一致。
> 读者：编译器成员（`@compose` 处理器 / JsCodeGen 双侧）、SfA 插件维护者、Android IDE 成员。
>
> **设计定案（用户）**：`@compose` 部分编译成 Kotlin Compose 函数；Compose 函数内部继续用
> WebView 跑 subl 编译出的 JS。**布局 → Kotlin Compose，逻辑 → JS，严格解耦。**
> **路线定案**：生成 `.kt` 源码 + Gradle 编译；不做 ComposeView 运行时映射（那还是运行时解释）。

---

## 0. 一句话模型

```
subl 源（app/*.subl）
   ├── @compose 视图树   ──(编译期展开)──►  GeneratedCompose.kt（真 Compose 函数）
   ├── 其余函数（逻辑/状态）──(既有 JsCodeGen)──►  app.js  ──► assets/app.js ──► WebView
   └── 两边的连接点：Compose 读 JS 状态（pushState）、Compose 的交互回写 JS（callJs）
```

**不变量**

1. 生成的 Kotlin **不含任何 subl 求值器**：它是普通 Compose 代码，可被 `flutter`/`gradle` 静态编译，
   Compose 编译器插件正常推断重组。
2. 生成的 Kotlin **不依赖运行时视图解释**：没有「JSON 树 → View」映射，布局结构在编译期已固化。
3. JS 侧**不再需要渲染**：`@compose` 工程的 JS 只为逻辑（持久化、引擎、校验）服务；
   桌面/node 目标为了可测性仍走「JS → 视图 JSON」快照，两者由**同一份 AST** 生成，契约由 §5 测试盯住。

## 1. `@compose` 与 `@composable` 的关系

| 注解 | 语义 | 编译目标 |
| --- | --- | --- |
| `@composable`（既有） | 函数体内可构造 `@view` 结构体；返回视图。JS 端生成视图 JSON 树（`layout` 桥）。 | JS（`app.js`） |
| `@compose`（新增） | 函数的**返回视图树**由 SfA 编译器**在编译期等价展开为 Kotlin Compose 调用**；函数体本身（可变状态、计算）仍编译为 JS。 | Kotlin（`GeneratedCompose.kt`）+ JS |

- `@compose` 函数**必须是** `@composable`（视图构造纪律不变），且返回类型是某个 `@view` 结构体。
- 一个工程可以两种都有：入口页面用 `@compose`，其余内部函数（行渲染、片段）继续 `@composable` + JS。
  但 **`@compose` 函数体内出现的所有视图构造都会进 Kotlin**（递归/列表渲染也一并展开为 `forEach`）。
- 没有 `@compose` 的工程完全不受影响：只产出 `app.js`，走旧的 `DshBridge` 运行时视图（协议 v2）。

## 2. 主产物：`GeneratedCompose.kt`

### 2.1 位置与命名

| 项 | 约定 |
| --- | --- |
| 文件 | `<android-app>/app/src/main/java/<namespace>/gen/GeneratedCompose.kt` |
| 包 | `<namespace>.gen`（namespace 取自 `AndroidManifest`/`build.gradle.kts`，默认 `functor.sublimation.android`） |
| 函数名 | `Subl<模块路径>_<函数名>`：模块 `app` 的 `content` → `SublApp_content`；嵌套模块 `app.ui` 的 `home` → `SublAppUi_home` |
| 入口 | `@Composable fun SublRoot()`：分派到 `@compose fun main.content`（工程约定：`main.subl` 的 `content` 是首页根；无则取唯一的 `@compose` 函数） |
| 幂等 | 每次编译**整文件重写**；带 `// <auto-generated by SfA — do not edit>` 首行。未变化则字节级不变（便于增量构建）。 |

### 2.3 每个 `@view` 结构体 → 一个 `@Composable` 渲染函数

```kotlin
@Composable
fun Subl_Box(
    modifier: Modifier,
    orientation: String,
    backgroundColor: Color,
    scrollable: Boolean,
    spacing: Int,
    arrangement: String,
    wrap: Boolean,
    onClick: String,
    content: @Composable () -> Unit,
) { ... }

/** 命名参数构造点调用：每个构造点按「实参值 → 参数」位置映射，缺省值内联为字面量。 */
@Composable
fun Box_call_<构造点id>(...)   // 可省略：调用点直接展开即可
```

**构造点展开规则**（`X(字段 = 实参, ...) { 子视图... }`）：

```kotlin
Subl_<X>(
    modifier = <实参 js[]> 的 Modifier 表达式（§3）,
    <其余字段> = <实参的常量折叠结果> 或 <宿主读取表达式>（§4）,
    onClick = <回调 key 的字面量字符串>,
) {
    <子视图 1 展开>
    <子视图 2 展开>
}
```

- **实参必须可静态确定**，否则按 §4 分类：字面量/常量折叠 → 内联；宿主状态（storage/screenWidth/别的 JS 函数返回） → `stateOf(...)` 读取 + 回退默认值。
- **尾随 lambda（body）**：编译期已经由 `@view` 处理器擦除为 `children`，生成器遍历 `children` 逐项展开（不用手写 DSL 作用域）。
- **递归/列表渲染**：`rowsBody(rest)` 这类对列表子项的递归调用，生成器展开为 `xs.forEach { item -> ... }`（`xs` = 该实参在 JS 侧的 List 值）；`when (xs)` 的 Nil/Cons 分支还原成 `if (xs.isEmpty())` / `xs.forEach`。
  ⟶ **一条 `@compose` 函数覆盖任意长度列表**，回调 key 用 `forEachIndexed` 的 `index`（§3.4）。

## 3. Modifier 链 —— 编译期折叠

### 3.1 语言侧形状（SfA 标准库 `app/Modifier.subl`）—— t54 定稿

语言只能构造**枚举与命名结构体**，没有方法定义，因此「链」用**同名链式函数的重载**表达
（`width(4).height(20)` ⇔ `height(width(4), 20)`；F# 模块函数风格，Compose 的 `Modifier.f().g()` 等价物）。
**链的类型就是 `List[MKind]`**（t54 定稿：视图字段 `modifier: List[MKind] = emptyList()`，
不再包 `@view struct Modifier`）：

```subl
enum MKind {
    Plain(), FillMaxSize(), WrapContent(), Padding(Nat), Width(Nat), Height(Nat),
    FillWidth(), FractionWidth(Rat), FillHeight(), FractionHeight(Rat),
    Padding4(Nat, Nat, Nat, Nat), PaddingH(Nat), PaddingV(Nat), Weight(Rat),
    Background(Str), Clip(Nat), Alpha(Rat), Flash()
}

fun width(n: Nat): List[MKind]                     // 链的起点
fun width(m: List[MKind], n: Nat): List[MKind]     // 链式项（同名重载）
fun plus(a: List[MKind], b: List[MKind]): List[MKind]   // 链拼接：a 的元素在前
// 短路（与 Compose 同义）：自带 Fluent 的视图可选字段自动补 §4 的「短路接收者」
fun Text(shortModifier, text: Str = "", ...)      // 参数名可写成可选字段名
```

链的**规范顺序**＝源码书写顺序（从左到右）；序列化为有序数组 `modifiers`（见协议 v2 文档 §1.2）。

> **t54 纠偏（重要）**：本节早期版本写的是 `M*` 前缀元素构造函数 + `Modifier` 包装结构体。
> 实测（SfA app/ 全量编译）该方案不可行：
> - **R5/R6 汇总根因**：`@view struct Modifier` 的字段默认值 `Plain()` 会被 checker 解析成 **MKind 的构造子**
>   （枚举构造子与同名普通函数共存时优先 ctor），于是所有带默认值的视图字段报
>   「字段 modifier 的默认值 MKind 与 Modifier 不符」——全工程几十处。
> - **对齐元素必须删**：`Center` 与 core `Alignment.Center` 冲突（`E-TYPE-MISMATCH 实参 0 Alignment`），
>   对齐改走容器 `contentAlignment` 字段（7 档，KT/Compose 两侧映射见协议 v2 §3）；
>   `fun size` 与 core `size[T]` 冲突，同样删除（用 `.width().height()` 表达）。
> - 定稿写法下 **R1 的规避不再需要 `M*` 前缀**：链式函数与视图字段 (`modifier: List[MKind]`) 不同名，
>   裸调用 `FillMaxSize()` 不再进字段作用域（§7 R1 描述的冲突随 `Modifier` 包装的消失而消失）。
>   §3.2 生成规则表里的 `M*` 名称请按 MKind 构造子原样理解为`FillMaxSize()`/`Width(n)` 等。

### 3.2 生成规则

| 链元素（`MKind`） | 生成 |
| --- | --- |
| `Plain()` | `Modifier`（空；语言侧空链用 `emptyList()`，序列化后为空数组） |
| `MWidth(n)` / `MHeight(n)` | `.width(n.dp)` / `.height(n.dp)`（**nat → dp**：Compose 的 dp 与 SfA 的 nat 同尺度） |
| `MFillMaxSize()` | `.fillMaxSize()` |
| `MWrapContent()` | `.wrapContentSize()`（Compose 3 无 wrapContent；对 `size` 效果等价） |
| `MPadding(n)` | `.padding(n.dp)` |
| `MPadding4(l,t,r,b)` | `.padding(start=l.dp, top=t.dp, end=r.dp, bottom=b.dp)` |
| `MPaddingH(h)` / `MPaddingV(v)` | `.padding(horizontal=h.dp)` / `.padding(vertical=v.dp)` |
| `MFillWidth()` / `MFillHeight()` | `.fillMaxWidth()` / `.fillMaxHeight()` |
| `MFractionWidth(f)` / `MFractionHeight(f)` | `.fillMaxWidth(f)` / `.fillMaxHeight(f)`（f ≤ 1） |
| `MWeight(w)` | **仅 Row/Column 的直接子级**：把该子视图的修饰符尾接 `Modifier.weight(w)`（显式传参，见下） |
| `MBackground(hex)` | `.background(Color(0xAARRGGBB))`（与 `backgroundColor` 字段同色时去重） |
| `MClip(corner)` | `.clip(RoundedCornerShape(corner.dp))` |
| `MAlpha(f)` / `MRotate(deg)` | `.alpha(f)` / `.rotate(deg)` |

- **Weight 与函数作用域**：`Modifier.weight` 只在 `RowScope`/`ColumnScope` 内可见。生成器对所有含
  `MWeight` 的**子**修饰符统一改走**带 weight 参数的重载**：`Subl_Box(modifier = ..., weight = 1f)`——
  重载内部在作用域里补 `.then(if (weight != null) Modifier.weight(weight) else Modifier)`，从而不依赖调用点作用域
  （LazyColumn 的 `item{}` 里也能用）。**生成器必须给每个 `@view` 渲染函数都产出这个带 weight 的重载**。
- **链条常量折叠**：链上所有实参都是字面量/常量表达式时，直接生成**一段字面量修饰符代码**
  （`.fillMaxHeight(0.45f).padding(24.dp)`），不留 `MKind` 值的运行时代数。
  含宿主状态（`screenHeight()`）时退化为 `stateOf` 读取（§4）。

### 3.3 序列化侧（桌面/node 目标）

链 → `modifiers` 有序数组（协议 v2，见 `docs/视图渲染协议 v2.md`），元素为 `{"tag":"Width","0":4}`。
**两侧同源**：Kotlin 生成的修饰符序列与 JS 的 `modifiers` 数组必须同序（§5 测试：比较序列的 tag 列表）。

## 4. 逻辑 ↔ 布局 的桥（严格解耦的落点）

`@compose` 函数体里的**非视图语句**（`@mut var` 声明、赋值、`unchecked f(...)` 调用）仍编译进 JS。
Compose 只关心**它渲染所需的值**。三类：

| 类别 | 判据 | 生成 |
| --- | --- | --- |
| **常量**（可折叠） | 字面量、纯字面量运算、`when` 常量分支 | 内联字面量（不查 JS） |
| **宿主状态**（读） | `storageGet`、`screenWidth/Height/Density`、`fmtTime(timeNow())`、用户 `@impure` 读数函数 | `val v by DshComposeHost.stateOf("<slotKey>", <默认字面量>) { it.optInt("n") }` |
| **事件**（写 + 跳转） | `onClick/onChange/onToggle/onConfirm/onDismiss` 等回调字段 | `DshComposeHost.callJs("<回调 key>", <JSON 参数>)`（键即 JS `__dshFn_*` 槽位） |

**slotKey**：`<模块>.<函数>.<变量名>`（如 `app.content.meds`）。JS 侧 `DshComposeHost` 在每次
`__dshDshPush`（编译器在 `@compose` 函数执行的末尾注入）时把该函数的**所有 `@mut` 局部变量**
序列化为 JSON 推给 Kotlin；Kotlin 侧 `stateOf` 用 `snapshotFlow`/回调把值写进 `mutableStateOf`，
从而触发真重组。**这就是「不用运行时解释也能重组」的方式**：状态推送是数据，不是视图。

- 状态字段缺省值 = 结构体字段默认值（编译期已知），首次推送前 Compose 用默认值渲染，不留空白。
- 值类型映射见 §4.1；**不可序列化的值**（函数值、视图实例）不进状态槽。

### 4.1 值映射表

| subl | Kotlin | JSON |
| --- | --- | --- |
| `Str` | `String` | `"s"` |
| `Nat`/`Int` | `Int` | `3` |
| `Rat` | `Float` | `0.45` |
| `Bool` | `Boolean` | `true` |
| `List[T]` | `List<T>`（JS 数组同构） | `[...]` |
| 结构体（`MedCard` 等） | 同名字段 `data class`（生成到 §2.1 同文件） | `{"字段":值}` |
| 枚举 | `enum class`（构造子 → 值类；带参构造子生成 `data class`） | `{"tag":"Width","0":4}` |
| 颜色字面量 | `Color(0xAARRGGBB)` | 原字符串 |

### 4.2 宿主接口（SfA 侧已落地，见 `GenRuntime.kt`）

```kotlin
object DshComposeHost {
    fun <T> stateOf(key: String, default: T, parse: (JSONObject) -> T): State<T>
    fun callJs(key: String, argsJson: String = "[]")
    fun pushState(fn: String, stateJson: String)     // JS → KT 入口（WebView JavascriptInterface）
}
```

## 5. 视图 → Compose 组件映射（编译期固化，运行时零映射）

| `@view` | 生成（M3） | 备注 |
| --- | --- | --- |
| `Box` | `Column`（vertical）/ `Row`（horizontal）/ `FlowRow`（`wrap=true`） | `spacing` → `Arrangement.spacedBy`；`arrangement="SpaceBetween"` → `Arrangement.SpaceBetween`；`scrollable` → `verticalScroll`/`horizontalScroll`；`onClick` → `.clickable { callJs(...) }`；含 `FloatingButton` 子 → 外层 `Scaffold(floatingActionButton=…)` |

| `Button` | `Button(onClick) { 子视图 }`（**透传子视图**，不再只取首个 Text） | `style="text"` → `TextButton` |
| `TextButton` | `TextButton(onClick) { … }` | 新 |
| `FloatingButton` | `ExtendedFloatingActionButton(onClick, icon={ Icon(IconName) }, text={ Text(label) })` | 由父 `Scaffold` 托管 |
| `Card` | `Card(colors = CardDefaults.cardColors(containerColor), shape = RoundedCornerShape(r))` + `CardDefaults.cardElevation(e)` | 圆角/阴影真值 |
| `TextField` | `OutlinedTextField(value, onValueChange = { callJs(onChange, [it]) }, label, isError, supportingText, singleLine)` | 受控：value 来自状态槽，onChange 走 `callJs`（不再重建丢焦点） |
| `Switch` / `Checkbox` / `Slider` / `Progress` | M3 同名组件 | `onToggle`/`onChange` → `callJs` |

| `Icon` | `Icon(Icons.Filled.X)`（X 由名字表映射，未知名 → `Icons.Filled.Circle` + 编译告警） | 新 |
| `AlertDialog` | `if (visible) AlertDialog(onDismissRequest = { callJs(dismiss) }, confirmButton, dismissButton, title, text)` | `visible` 来自状态槽；新 |
| `BottomSheet` | `ModalBottomSheet(onDismissRequest, sheetState = rememberModalBottomSheetState(skipPartiallyExpanded = true))` | 新 |
| `Chart` | `Subl_ConcentrationChart(series, labels, modifier)`（生成一个 Canvas 绘制函数：多序列 + 图例 + 渐变 + 轴） | 多序列 |
| `TimelineView` | `Column { items(times.indices) { Row { Text(time); Box(dot); Text(label) } } }` | 叶子数据视图 |
| `Spacer` | `Spacer(Modifier.size(n.dp))` | |

**动画最小集**：`Modifier.flash()`（`rememberInfiniteTransition` + 1.0↔0.25 透明度，650ms Reverse）——
语言侧由 `MFlash()` 链元素或 `flash=true` 视图字段表达；JS 侧对应 `AlphaAnimation`。

**主题色**：`Theme.subl` 的常量 → `GeneratedTheme.kt`：`lightColorScheme(primary=Color(0xFF00695C), …)` +
`SublTheme { SublRoot() }`。视图字段传 `"$primary"` 这类**主题别名**时，生成 `MaterialTheme.colorScheme.primary`，
而不是硬编码十六进制；`"#AARRGGBB"` 直接 `Color(0xAARRGGBB)`。

## 6. 编译期顺序（SfA 插件要做的事）

1. 处理器链跑完后，对每个 `@compose` 函数做**一次 AST 遍历**得到「构造点树」：
   节点 = 视图结构体名 + 字段实参表达式 + 子节点；遇到非视图调用（`rowsBody(rest)`）沿被调函数继续展开，
   遇到 `List` 参数递归 → `forEach` 模板。
2. 常量折叠（§4 第一类）；剩余实参按 §4 分类打标签（state / event）。
3. 发射 `GeneratedCompose.kt`（§2/§3/§5）。
4. JS 侧：`@compose` 函数体照旧生成（逻辑）；额外在函数末尾发射 `__dshDshPush("<模块>.<函数>", {...})`。
5. 失败模式（**都要给可读诊断，落在 subl 源码位置**）：
   | 码 | 触发 | 处理 |
   | --- | --- | --- |
   | `E-COMPOSE-NO-STATIC-TREE` | 构造点出现在非常量分支且不是受支持的 `when`/`if` 形态 | 报错并指向该节点 |
   | `E-COMPOSE-UNKNOWN-VIEW` | `@view` 结构体没有生成的映射规则（新组件忘了登记） | 报错，提示在 SfA 的 view_map 登记 |
   | `E-COMPOSE-DYNAMIC-CALL` | 构造点来自调用 JS-only 函数的返回值 | 报错（@compose 树必须在编译期可见） |

## 7. 语言侧形状（实测确认，t54 2026-10-28）

编译器当前能力下，**链式 API 唯一可用的写法**（都在 SfA `app/Modifier.subl` 里落地并通过编译）：

- **链式函数必须用「首参接收链」的重载**：`width(n)` 起链、`width(m, n)` 挂链——两个独立函数，**不能**用「方法定义/同名成员」。
- **链的类型是 `List[MKind]`**（不是 `Modifier` 包装结构体）：视图字段 `modifier: List[MKind] = emptyList()`。
  t54 实测：`@view struct Modifier` 包装方案**不可用**——它的字段默认值 `Plain()` 会被 checker 解析成
  MKind 构造子（ctor/同名函数共存时优先 ctor），于是**全部**视图字段默认值报
  `字段 modifier 的默认值 MKind 与 Modifier 不符`（前版本文档把这条误判为 §8 R5 的独立 bug，实为同一根因）。
- **链元素不能与 core 符号同名**：`Center` 与 core `Alignment.Center` 冲突（`实参 0 Alignment 与形参 MKind 不符`），
  `fun size` 与 core `size[T]` 冲突——已删除 `Center`/`size`，对齐走容器 `contentAlignment` 字段。
- **空链写 `emptyList()`**：`Plain()` 会命中枚举构造子 `Plain()`；序列化后是空数组（KT 侧 applyModifiers 空数组即无操作）。
- **t54 编译结论**：按上述写法 SfA `app/` 全量 `compile <dir>` **exit=0 / 0 errors**（11 个视图 + 修饰符库 + main/meds/timeline 三个 composables），旧 §7 描述的「嵌套视图构造 E-TYPE-MISMATCH」**已不复现**——该现象的触发条件就是 `Modifier` 包装结构体本身；结构体去掉后阻塞消失。仅剩一处**与 t54 无关的预存代码生成缺陷**：
- **编译器缺陷（需修，非 t54 范围，已上报）**：`JsCodeGen.kt:1433` 的 `elementAt` 快路径把实参表达式直接绑定进
  `( () => { const a = $xs; const i = $i; ... } )()`——当实参恰为标识符 `i` 时生成 `const i = i`（TDZ，
  `ReferenceError: Cannot access 'i' before initialization`）。修复：alpha-rename 内层绑定。
  SfA 侧临时规避（`meds.subl` 形参改名为 `idx`）。
