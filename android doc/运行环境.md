# 运行环境与依赖同步

> 本文档说明 SfA 仓的**运行环境约定**：编译命令从哪里运行、处理器与标准库从哪里来、
> 如何同步。事实来源：编译器 cli/Main.kt 与 annotationproc 模块（BuiltinProcessors 按
> CWD 相对路径装载）。

## 一、为什么有这个约定

Sublimation 编译器按 **CWD（当前工作目录）相对路径**装载两样东西：

| 编译器内部 | 相对路径 | 用途 |
| --- | --- | --- |
| `BuiltinProcessors.DEFAULT_DIR` | `annotation processer/` | 默认处理器目录：其下每个 `.subs` 文件 = 一个处理器（文件名 = 处理器名 = 关注注解） |
| `ScriptProcessor` 的 `stdlibDir` | `core/` | 处理器脚本自身的标准库：脚本类型检查要见到 List/Cons/Nil 等 core 符号 |

因此「从 SfA 仓根运行 compile」时，仓根必须同时存在 `annotation processer/` 与 `core/`。
缺 `core/` 的现象：`E-PROCESSOR-ERROR 脚本处理器 android 执行失败：脚本类型检查失败：
E-UNBOUND-NAME 未知类型 List[Str] / 未知构造子 Cons`。

## 二、依赖的来源与去向

**真源 = 主仓 Sublimation**（`F:\KotlinProject\Sublimation`）。
SfA 仓是消费方，各副本的用途与入库状态：

| 副本 | 来源 | 用途 | 入库 |
| --- | --- | --- | --- |
| `annotation processer/`（仓根） | 主仓 `annotation processer/` | CWD=仓根时编译器的默认处理器集（allMut/android/composable/view） | 是 |
| `app/core/` | 主仓 `core/` | 编译输入：app 工程模块树里的 core 标准库 | 是（随主仓更新） |
| `core/`（仓根） | 主仓 `core/` | 处理器脚本的 stdlib（CWD 可见性），仅运行环境 | 否（.gitignore，脚本同步） |
| `sdk-lite/annotation processer/` | 主仓 `annotation processer/` | CWD=sdk-lite 时的本地快照 | 否（.gitignore） |

> 为什么仓根 `core/` 不入库：core 的真源在主仓，入库副本必然漂移（`app/core/` 此前就是
> 箭头统一（程序位 `=>`、命题位 `→`、ASCII `->` 非法）之前的旧快照，导致整仓无法
> 用当前编译器编译）。仓根副本只服务于编译器
> 的 CWD 装载，由脚本保证与真源一致，比手动维护入库副本更可靠。

## 三、同步：scripts/sync-deps.ps1

```powershell
# 从仓根运行（自动探测主仓）
powershell -ExecutionPolicy Bypass -File scripts/sync-deps.ps1

# 显式指定主仓
powershell -ExecutionPolicy Bypass -File scripts/sync-deps.ps1 -MainRepo D:\...\Sublimation

# 或设环境变量
$env:SUBLIMATION_REPO = "D:\...\Sublimation"
```

脚本动作（可加 `-SkipCore` / `-SkipProcs` / `-SkipSdkLite` 跳过）：

1. 主仓 `core/` 镜像到仓根 `core/` 与 `app/core/`（先清后拷，删除也会传播）；
2. 主仓 `annotation processer/` 的 `.subs` 写到仓根 `annotation processer/` 与
   `sdk-lite/annotation processer/`，**统一 LF、无 BOM**（t11 起的约定）。

探测顺序：`-MainRepo` 参数 > `$env:SUBLIMATION_REPO` > 常见路径
（`F:\KotlinProject\Sublimation` 等），找到的目录须同时含
`annotation processer\android.subs` 与 `core\logic\logic.subl` 才认作主仓。

**何时跑**：拉取/更新主仓后、首次 clone 本仓后、编译报「未知类型 List[Str]」等
脚本符号缺失时。

## 四、从哪运行 compile

**约定：从 SfA 仓根运行。** 这样编译器装载的是本仓 `annotation processer/`（已由脚本
与主仓对齐），脚本 stdlib 取本仓 `core/`。

```bat
cd "F:\SublimationProject\sublimation for android"

java -cp <编译器 jars> sugared.functor.MainKt compile app -o app/out.js ^
    -A appDir=<android-app 路径> -A jsPath=app/out.js ^
    -A outDir=<APK 输出目录> -A sdkDir=<sdk-lite 路径>
```

- 不给 `-A appDir` / `-A jsPath` 时，`@postcompile` 的 APK 构建阶段自动跳过（只生成 JS）；
- `compile app` 以 `app` 为编译根（模块模式：app/core + 安卓标准库 + main.subl 一起检查）；
- 需要 APK 时按上例给全 `-A`（详见 README 的端到端流程与 android doc/精简工具链.md）。

> **不要从主仓根运行 SfA 的编译**：CWD=主仓根时编译器会装载**主仓自己的**
> `annotation processer/` 副本而非本仓的——虽然二者经脚本同步后内容一致，但
> 那会绕过本仓的副本，让「真源单点化」失去意义。

## 五、验证清单

每次改动运行环境后，从仓根跑一遍冒烟编译，确认：

1. `compile app` 退出码 0；
2. 输出里 `H-ANDROID-BUILTIN` 提示覆盖全部 29 项内建（基础 3 + 生命周期 7 +
   androidRecompose 1 + 意图 6 + 平台能力 12，含 fmtTime）。

示例：`java -cp <jars> sugared.functor.MainKt compile app -o app/out.js`。
